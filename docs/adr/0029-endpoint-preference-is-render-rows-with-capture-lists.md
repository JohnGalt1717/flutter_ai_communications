# Endpoint preference is ordered render rows with capture lists

Host persistence and UI, Communications manager resolution, and a separate Camera preference are unchanged from ADR-0006. What changed is the audio list: Endpoint preference is an ordered list of render Endpoints, each with an ordered list of capture Endpoints, not a mixed Endpoint-id list that fills capture and render independently. A hardware Pair remains catalog identity and editor prefill; the same capture Endpoint may appear on many rows. Empty preference is still platform-default complete Pairs. Selecting a render on a live Session auto-completes capture from that row (or the hardware Pair, or a capture-only walk if unlisted and unpaired) and is not written back; the user may then pick any capture. Failed Route convergence marks that `(render, capture)` unusable for the Session and continues the same walk.
